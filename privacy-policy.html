Privacy Policy

Effective date: 11 October 2026 · Last updated: 11 October 2026

Current status: A local Facebook Page publishing tool is available but has not yet been connected to a Page. It runs on the operator’s computer and requires a separate, explicit confirmation before each post is sent to Facebook.

This policy explains how the Gold Market Intelligence service (“the service”) handles information when its operator uses the local publisher to prepare and publish research content to a Facebook Page. The service is operated by the individual listed under Contact. This local tool is not a hosted web application.

Information the service may handle

When the operator connects a Facebook account, the local tool receives and temporarily processes only information needed for the requested publishing workflow, such as:

  • Facebook Page names, Page IDs, and Page publishing-task details returned by Meta, to let the operator choose a Page they are authorized to manage.
  • Short-lived user authorization and Page access tokens returned through Meta’s OAuth flow. The local tool uses these tokens only for listing Pages and carrying out a publication the operator explicitly confirms.
  • The prepared post caption and chart images, and the post identifier returned by Meta after a successful publication.

The gold-market reports and graphics may contain public market-price information from the sources identified in the relevant report. They are not personal information about the Page operator.

How information is used

The operator’s browser connects to a service bound to the operator’s own computer (localhost). Meta handles the sign-in and authorization. The tool uses returned Page information to show the Pages available for publishing, then displays the exact caption and images for review. It uploads the images and creates a Page post only after the operator checks the confirmation box and selects the publish button. It does not use Page access to read private messages or personal profile information, and it does not publish unrelated content or post on a schedule.

Sharing and service providers

The service does not sell personal information. During authorization, the browser communicates with Meta and the local tool sends OAuth requests to Meta. After explicit publish confirmation, the caption and images are sent to Meta Platforms, Inc. to create the requested Facebook Page post. The local tool is not hosted by a cloud provider and is designed not to send Page data to any other service. GitHub may independently process technical information when hosting this policy page; see GitHub’s Privacy Statement below.

Storage and retention

The local tool keeps OAuth and Page access tokens, Page details, and the returned post ID in the running process’s memory only. It does not write those tokens or Page data to a database or file, and it suppresses HTTP request logging. Browser session data expires after one hour and expired sessions are removed from memory by the running tool; stopping the tool clears all remaining session data. The operator’s Meta app ID and app secret are kept in a local environment file on the operator’s computer and are not shown in the browser interface. The tool does not retain a separate publication record after it stops.

Facebook posts and uploaded media sent to Meta are subject to Meta’s storage and retention policies. If a publishing attempt fails after image upload, unpublished images may remain on the Page; the operator should check the Page and remove them if appropriate. Facebook posts published at the operator’s request remain on the Page until the Page administrator or Meta removes them.

Your choices and deletion requests

The operator can stop future access by revoking the app’s authorization in Facebook settings. Because the tool is local and does not keep Page data after its process stops, the operator can clear locally held session data by stopping it. To request deletion of content or information held by Meta, use Meta’s tools and policies. To contact the service operator about this local workflow, email sam2021x@gmail.com. Do not email access tokens, app secrets, or passwords.

Security

The local tool binds only to the operator’s computer, uses a one-hour browser session, CSRF checks, and keeps authorization tokens in process memory rather than persisting them. These safeguards do not eliminate all risk. No transmission or storage system can be guaranteed to be completely secure. Do not share the computer while connected, or send passwords, access tokens, app secrets, or other credentials by email or in a support request.

Children

The service is intended for adults who manage a Facebook Page. It is not designed for children and does not knowingly seek to collect children’s personal information.

Changes to this policy

This policy will be updated when the service’s integration, data practices, or legal requirements change. The effective date at the top indicates when the current version was last published. Material changes will be reflected on this page before the changed data practice begins.
